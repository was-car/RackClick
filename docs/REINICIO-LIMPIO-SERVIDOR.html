RackClick 06 · Instalación en la nueva VM

El destino elegido es otra VM Windows Server 2025 con experiencia de escritorio, que no sea controlador de dominio. Los usuarios trabajan desde el navegador.

El servidor anterior es controlador de dominio de Active Directory. Su modelo de cuentas no corresponde al instalador de cuentas locales. La edición06 comprueba el rol antes de limpiar, instalar dependencias o crear cuentas. No se utiliza para quitar Active Directory ni convertir el controlador en servidor de aplicaciones.

00 · Preparar Windows de la nueva VM

  1. Instala Windows Server 2025 x64 con experiencia de escritorio. Utiliza una VM distinta del controlador actual.
  2. Asigna un nombre diferente; por ejemplo, RACKCLICK-APP, si está libre. No habilites el rol AD DS ni la promociones como controlador de dominio.
  3. Conecta la VM a la misma red de los navegadores. Debe tener su propia IP disponible. Si el controlador conserva 192.168.178.140, esa IP permanece en él: no la dupliques en la nueva VM.
  4. Puede permanecer independiente o unirse al dominio como servidor miembro. La cuenta de instalación debe tener permisos de administrador en esta nueva VM. RackClick creará sus propias cuentas locales de servicio y de aplicación.
  5. Comprueba que fecha/hora, red y DNS de Windows funcionan y que puedes iniciar sesión. El instalador no cambia IP, nombre, DNS ni pertenencia al dominio.

Este ZIP incluye la aplicación, runtime .NET10.0.12, PostgreSQL17.11, Visual C++ x64 y servicio Windows. No hace falta instalar SDK, Git, Node, Python, VS Code ni IIS. Usa disco NTFS local y deja espacio para aplicación, base y backups; el preflight exige al menos2GiB libres para empezar. Los backups aumentan con los datos.

01 · Abrir el paquete en la nueva VM

  1. Copia el ZIP06 a la nueva VM. En el Explorador, clic derecho → Extraer todo, en una carpeta nueva.
  2. Abre RackClick-Servidor-06. Haz doble clic en 00-LIMPIAR-Y-REINSTALAR.cmd y acepta el aviso de administrador.
  3. El paquete se verifica y extrae a un directorio privado nuevo. Comprueba el rol del equipo. En un controlador de dominio o si no puede verificar el rol, se detiene y genera un informe antes de archivar carpetas o crear cuentas.
  4. En la ventana de preparación, mira las dos rutas centrales. En una VM nueva deben aparecer como No existe. Pulsa Conservar anteriores e instalar, abajo a la izquierda; si no hay carpetas anteriores, no hay nada que archivar.

Si existen carpetas antiguas de RackClick, las conserva como hermanas RackClick-Previous-identificador, manteniendo datos y permisos. Referencias de servicios/tareas/procesos o puertos ocupados bloquean. No borra software ni bases ajenos.

02 · Configurar RackClick

  1. En el asistente, revisa IP de escucha y Nombre DNS o IP: deben ser los de la nueva VM. La propuesta se obtiene de su red. No copies la IP del controlador anterior.
  2. Deja HTTPS 5443 y PostgreSQL local 55441 si están libres. Para tu LAN, revisa 192.168.178.0/24 si sigue siendo la red correcta.
  3. Escribe el nombre de Systemhaus y el Administrador de RackClick deseados. Deja servicio RackClick, cuenta propuesta y Modo: New.
  4. Marca la autorización de confianza de la CA local, debajo de los campos. Pulsa Revisar e instalar, abajo a la izquierda, y confirma el resumen.
  5. Espera sin cerrar la ventana. Se verifican las etapas. Si Visual C++ solicita reinicio, reinicia la nueva VM y vuelve al CMD. Si falla, conserva el intento y envía el ZIP automático del Escritorio.

Usuarios de aplicación, cuentas Windows de servicio y roles PostgreSQL son identidades distintas. No hacen falta usuarios AD nuevos ni permisos de Domain Admin para el funcionamiento diario. El servicio usa una identidad local estándar y claves generadas localmente.

03 · Acceso y reinicio

  1. Al llegar al 95%, pulsa Acceso privado y consulta localmente las credenciales nuevas. No las envíes al chat.
  2. Pulsa Abrir RackClick. En el navegador, inicia sesión y comprueba Systemhaus.
  3. Guarda los trabajos y reinicia la nueva VM. Después ejecuta en su Escritorio RackClick-VERIFICAR-06-…cmd. Acepta permisos, selecciona la instancia y pulsa Verificar instalación.
  4. El100%técnico requiere observar ese arranque, servicio automático, HTTPS y backup. No equivale a adopción final del producto. Continúa después con tus QA en el navegador.

El CMD04 aportado anteriormente solo abre el panel de verificación del intento de aquella VM; no es un instalador ni se copia a la nueva. El paquete06 genera su acceso nuevo.

Los demás equipos usan la URL HTTPS de la nueva VM. Con esta CA privada, importa solo el certificado público RootCA.cer indicado por el panel en las autoridades raíz del cliente. No compartas PFX ni claves privadas. PostgreSQL queda local.

04 · Evidencia y recuperación

El instalador genera un informe saneado en el Escritorio al finalizar, también ante fallos. Incluye rol numérico del equipo y si pertenece al dominio, sin nombre del dominio ni contraseñas. Los informes234402 y234749 recibidos describían el mismo intento fallido al10%; la recuperación04 había terminado correctamente.

Conserva los informes y las carpetas Previous del controlador anterior. No se ha auditado ni modificado Active Directory. Una cuenta residual de aquellos intentos requiere identificar su SID/objeto antes de cualquier corrección; el paquete06 no borra ni modifica cuentas del dominio.

Las copias conservadas no se restauran automáticamente sobre la instalación nueva. Backup/Restore PostgreSQL y JSON de RC9 son formatos distintos. Los certificados generados duran90días y requieren renovación antes de vencer, sin promesa de renovación automática en esta candidata.
