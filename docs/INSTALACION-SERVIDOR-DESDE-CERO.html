RackClick · instalación desde cero

Windows Server 2025 x64 con escritorio. Los usuarios trabajan desde el navegador.

Edición 06 · 25.10.2026. Para la nueva VM Windows Server 2025 con escritorio, sin rol de controlador de dominio. Puede ser miembro del dominio. El instalador ahora comprueba este requisito antes de archivar carpetas, instalar CRT o crear cuentas. El controlador actual queda para Active Directory. Usa en la nueva VM su propia IP, distinta de la del controlador; no copies 192.168.178.140 si sigue asignada a este.

Candidata habilitada para instalación y QA en tu servidor. El asistente comprueba el resultado real de cada etapa. Las pruebas de servicio, permisos elevados y reinicio se completan en la VM; no se presentan como ya ejecutadas ni como adopción final del producto.

00 · Extraer el paquete

  1. Copia el ZIP al servidor. En el Explorador, clic derecho sobre el ZIP → Extraer todo. Abre la carpeta extraída RackClick-Instalador. No ejecutes los archivos desde dentro del ZIP.
  2. El paquete incluye aplicación, runtime .NET10.0.12, PostgreSQL17.11, Visual C++ x64 firmado, servicio y herramientas. No necesitas instalar SDK, Git, Node, Python, VS Code ni IIS.
  3. Conserva los intentos anteriores. La nueva instalación usa una carpeta y base nuevas; no borra bases, servicios ni cuentas ajenos.

01 · Instalar con una sola entrada

  1. Haz doble clic en INSTALAR-RACKCLICK.cmd. Acepta el aviso de permisos de Windows. No tienes que copiar comandos PowerShell.
  2. En el centro del asistente, revisa IP de escucha y Nombre DNS o IP: se propone la IP del propio servidor. Conserva HTTPS5443 y PostgreSQL55441 si están libres. La red autorizada debe ser la LAN que utilizarán tus navegadores. No se cambia la configuración IP/DNS de Windows.
  3. En Nombre de Systemhaus escribe el nombre deseado. En Administrador de RackClick, conserva Wascar o escribe el nombre deseado. Deja el servicio RackClick y su cuenta propuesta.
  4. Para una instalación vacía deja Modo: New. No selecciones Restore para un JSON de RC9; Restore recibe un backup PostgreSQL con manifiesto y dump.
  5. Debajo de los campos, marca Autorizar confianza de la CA local. Pulsa Revisar e instalar, abajo a la izquierda, revisa el resumen y confirma.
  6. Espera sin cerrar la ventana. Se verifican archivos, CRT, cuenta, permisos, base, esquema, HTTPS, servicio, firewall y backup. Si Visual C++ exige reinicio, el asistente lo indicará antes de crear la instancia: reinicia Windows y vuelve a ejecutar el mismo CMD.

02 · Abrir la web y las credenciales

  1. Cuando aparezca Preparada, la barra queda al95%: aplicación/HTTPS/backup están comprobados; falta observar el reinicio.
  2. Pulsa Acceso privado. Se abre localmente el archivo con username y password de la nueva cuenta de aplicación. No las envíes al chat ni las anotes en el informe de QA.
  3. Pulsa Abrir RackClick. En el login del navegador, copia ese usuario y contraseña. El nombre de Systemhaus debe ser el elegido.

03 · Reiniciar y verificar

  1. Guarda cualquier otro trabajo y reinicia Windows desde Inicio → Encendido → Reiniciar.
  2. Después de arrancar, abre VERIFICAR-INSTALACION.cmd del mismo paquete. El panel identifica la instalación por recibo, rutas e identidad; no reinstala encima.
  3. Selecciona la instalación y pulsa Verificar instalación. Solo mostrará100% técnico si observa un arranque posterior, servicio automático correcto, HTTPS listo y tarea diaria de backup íntegra. Los errores conservan95% o un fallo explícito.
  4. Abre la web sin arrancar PostgreSQL ni la aplicación manualmente. Ya puedes comenzar QA funcional. El100% técnico del instalador no equivale al porcentaje global del proyecto ni a la aceptación final de Wascar.

04 · Navegadores de otros equipos

Abre la misma URL HTTPS publicada por el asistente. Los clientes no necesitan instalar RackClick ni una base de datos.

Con una CA privada, importa únicamente el certificado público RootCA.cer de la carpeta administrativa indicada en el recibo en las autoridades raíz de confianza del equipo cliente. El administrador del servidor puede copiar ese archivo público; nunca compartir el PFX, la contraseña TLS ni claves privadas. El nombre/IP utilizado debe coincidir con el certificado. No omitir avisos TLS.

La entrada del firewall se limita al puerto HTTPS y a la red elegida. PostgreSQL escucha solo en127.0.0.1. No se apaga el firewall ni se abre PostgreSQL a la LAN.

05 · Backup y restauración

  1. El servicio usa una tarea diaria a las03:00, hora local. Cada copia tiene una carpeta nueva; no se eliminan copias automáticamente. El instalador ejecuta y verifica una copia inicial y una ejecución real de la tarea.
  2. En VERIFICAR-INSTALACION.cmd, selecciona la instancia y pulsa Exportar backup. Elige una carpeta local/USB con NTFS. Se exportan manifiesto y dump a una carpeta nueva y se crea un archivo hermano con el SHA256 del manifiesto. Conserva una copia fuera del servidor; contiene datos de la aplicación.
  3. Para recuperar, usa INSTALAR-RACKCLICK.cmd → Restore, carpeta exportada y SHA256 del manifiesto. Usa otro puerto HTTPS/PostgreSQL y un nombre de servicio RackClick-Recovery- seguido de8–32 caracteres hexadecimales. Se crean nueva instancia, roles, claves, certificado y cuenta de recuperación; no se sobrescribe la principal.
  4. La restauración de un JSON de RC9 es un proceso diferente. No cambiarle el nombre ni presentarlo como un dump PostgreSQL.

06 · Si algo falla

No repitas la instalación encima ni borres carpetas. El asistente exporta automáticamente al Escritorio un ZIP de diagnóstico al finalizar. Envía ese ZIP. Incluye códigos y etapa, sin contraseñas, logs crudos ni datos de la base. Para otra copia, usa RECOPILAR-INFORME.cmd. Los archivos y copias originales se conservan.

La entrada de reinicio limpio conserva completas las dos carpetas anteriores como hermanas Previous, sin cambiar sus cuentas ni permisos. Comprueba que no haya servicios, tareas o procesos que dependan de ellas antes de moverlas. Un proceso todavía activo no se presenta como detenido ni se reintenta automáticamente.
