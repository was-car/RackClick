1. Copiar y extraer

  1. Copia RackClick-Preparacion-Cliente3-Servidor.zip únicamente al equipo o equipos que quieras preparar como servidor. En Windows11 abre el Explorador con Windows+E y entra en la carpeta donde lo copiaste. El nombre histórico del ZIP no obliga a configurar un «cliente3».
  2. Haz clic derecho en el ZIP → Extraer todo…. Elige una carpeta personal local, por ejemplo dentro de Documentos, y pulsa Extraer. Dentro de la carpeta extraída abre la subcarpeta Preparar-Cliente3-Servidor: ahí están los CMD. No los ejecutes desde dentro del ZIP ni extraigas el kit en una carpeta compartida o pública.
  3. Antes de ejecutarlo, comprueba el SHA256 del ZIP con la referencia externa entregada por Codex. En PowerShell: Get-FileHash -Algorithm SHA256 -LiteralPath '.\RackClick-Preparacion-Cliente3-Servidor.zip'. Si no coincide, conserva el archivo y comunica el resultado.
  4. Dentro de la carpeta extraída, MANIFIESTO.json enumera los seis archivos de entrada y sus hashes. Los lanzadores comprueban todos ellos antes de recoger datos. Esta comprobación detecta cambios; la confianza inicial depende del hash externo del ZIP.

2. En Windows Server

  1. En la carpeta extraída, haz doble clic en 01-DATOS-SERVIDOR.cmd. Usa una sesión normal, sin «Ejecutar como administrador».
  2. Espera el mensaje con el resultado y la ruta del JSON. Se guarda una copia nueva en la subcarpeta resultados. Pulsa una tecla para cerrar la ventana.
  3. En el Explorador abre resultados. Conserva el JSON cuyo nombre empieza por RackClick-Host-Server-.
  4. Ya has confirmado visualmente2025/24H2/build26100.33438. Si el inventario muestra algo distinto, conserva el informe y la diferencia; no cambies de versión. En ServerCore el JSON permite identificar el equipo sin una ventana gráfica.

Si Windows11 sólo se usa para navegar, omite esta sección. Cuando el servidor esté operativo, el usuario abrirá su direcciónHTTPS e iniciará sesión; no tendrá que instalar la aplicación ni ejecutar un CMD.

  1. Si quieres preparar Windows11 para alojar el servidor, abre la carpeta extraída y haz doble clic en 02-DATOS-WINDOWS11-SERVIDOR.cmd.
  2. Espera el resultado. En la subcarpeta resultados, conserva el JSON cuyo nombre empieza por RackClick-Host-Server-. El rolServer significa uso previsto, aunque el sistema operativo sea Windows11.
  3. El informe identifica el posible servidor; no instala nada ni certifica aún su compatibilidad. El certificado y la dirección efectivos se preparan durante C4.

5. Comportamiento y próximos pasos

Solo se consulta información local y se crean informes nuevos. No se hacen conexiones de red, cambios de firewall/confianza, instalaciones, reinicios, creación de usuarios, servicios o bases. Los lanzadores usan WindowsPowerShell5.1 x64 con política de ejecución limitada a ese proceso; no cambian la política persistente. Priorizan los módulos de ese WindowsPowerShell dentro del proceso, conservando las demás rutas de módulos. Una política obligatoria de la organización sigue prevaleciendo.

Tras recibir el inventario se comprueba la propuesta y se fijan: nombre/IP definitivo, origenHTTPS, certificado/confianza, identidad del servicio, rutas y destino de respaldo. Las versiones/builds de tu respuesta se conservan sin actualizarlas silenciosamente. La aplicación de LAN, SCM y recuperación se ensaya separadamente antes de entregarla para instalar. No abrir puertos ni importar certificados todavía.

El kit no consulta el router, concesionesDHCP, gateway o servidoresDNS. Esos datos y la reserva deIP se contrastarán antes de configurarLAN; mientras tanto se conservan los ajustes actuales.

Si una política de la empresa bloquea el script, copia el mensaje y comunícalo. No necesitas activar RDP, WinRM ni enviar acceso administrativo para esta recogida.
